## 链编排要点（跨运行一致）
- 主任务(每8h)全量；轻量刷新(once)增量。单链唯一 + 30 分钟硬隔离，全局同时仅 1 个 name 含「刷新」的 once。
- 空窗期候选集恒空 → 不建 once，链暂停，由主任务每 8h 兜底复核 + 刷新时间戳。
- **【铁律·写完即推送】** 写完 data.json 并通过 JSON 硬校验后**立即** `git add/commit/push`，早于早报存档/记忆/单链对齐。
- **【铁律·先拉后采/先拉后推】** 任何读取或 push 前 `git fetch origin && git rebase origin/main`。本仓库双机同步，前端机会提交 app.js/style.css/index.html。
- **【推送分叉处理】** push 被拒(non-fast-forward)且远端被前端提交抢先：`git stash` 无关 → `git fetch` → `reset --hard origin/main` → `checkout <本任务已校验 commit> -- data.json` → commit → push。**勿强推**。
- **【JSON 校验正确姿势】** 只依赖 `json.load` 是否抛错；不要断言字符串里没有 `\n`（json.dump 已转义，load 回来自然有真换行）。
- **【video.json 与四日期对齐】** `mergeVideo` 会把 data.json 没有的日期 push 成新 day → video.json 只保留四日期窗口内的日期，否则页面出现乱序日期块。
