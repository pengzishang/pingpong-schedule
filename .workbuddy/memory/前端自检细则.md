## 关键计数与成因

| 计数 | 正常值 | 说明 |
|------|--------|------|
| `pending__points` | 不固定 | 只统计 dayNote 要点块，有真实直播的日子不产出要点 → 变小属正常 |
| `day--next` | 窗口内有赛事时 = 0 | 下一站模块按窗口铁律隐藏；随之 `emeta__rank-item` / `next__lines` 也归零，**属正常** |
| `tag--soon` | 可能 >0 | 它也是「明天/后天」日期标签的默认 class（app.js:1864），**不是**倒数日徽章的证据 |
| `score-table` | >0 | 有 result 的场次渲染成分局表格（局分数字被拆进 `<td>`，整串比分在 HTML 里搜不到是正常的） |

## 三个高频踩坑

1. **排行榜只在 meta 块渲染**：`maybeRankList` 要求「`标签:项1 / 项2 / …`」且每项含数字、≥4 项；分块顺序 `isTV > isSeeds > isSched > isSquad`，**子句含「种子/排名/参赛/国乒/出战」会落进 seeds/squad** → 位次表措辞须避开这些词（测试要求 `emeta__rank-item` ≥10）。
2. **`next__lines` 需要 schedule 或 tv 段含 ≥2 个分句**（多句被 `；` 拼起来）；只有 1 句会退化成 `next__body`，`render.test.js` 第 20 例会挂 → 采集端保证写 ≥2 个含「转播/直播/CCTV」的子句。
3. **`nextEvent.note` 追加句必须命中分类关键词**，否则落进 `meta` 把首段撑成大坨：
   - `CCTV / 直播 / 转播 / 频道` → tv
   - `赛程 / 开打 / 决赛 / 对阵 / 签表` → sched
   - `国乒 / 出战 / 参赛` → squad

## 通用教训

- 修前端解析问题优先**在采集端改写法**，不动 app.js。
- 测试里「N 天后」语义的假数据一律相对 `new Date()` 动态算，别写死日期（曾把 `2026-09-11` 当「3 天后」，日期推进后变后天 → 模块隐藏 → 误报失败）。
- 判「今天」必须用**本地日期**拼接，**禁用 `toISOString().slice(0,10)`**（UTC 差 8 小时，凌晨场会误判）。
- **【2026-09-11 新踩坑】赛事进行中的「真实数据」测试，禁止写死淘汰/晋级名单或人数**。`computeSurvival` / `renderSurvivalBar` 两例原本硬编码「止步首轮 3 人（王艺迪/蒯曼/黄友政）」，陈垣宇 1/8 出局后立刻误报失败。
  **正解**：只断言**已成定局的不变项**（如首轮出局三人必在淘汰集），人数/画叉数改为**以 `computeSurvival` 结果为唯一事实来源**动态比对，并断言「存活 + 淘汰 = 总人数」。淘汰判定本身是对的，是测试期望过期，别去改 app.js。
- 空窗期结束后 `render.test.js` 末例需「窗口内存在可见空窗天才断言」守卫，否则必挂。
