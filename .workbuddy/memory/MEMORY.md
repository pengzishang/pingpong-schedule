# 项目记忆: pingpong-schedule 央视乒乓赛程

> 完整指令在项目根 `采集说明.md`（唯一指令源）。本文件只记**踩坑与判据**，不重复指令书。

## 铁律速查
1. **updatedAt 必刷**：每轮无论有无变更都 bump + push。诚实性靠 note 如实写「本轮复核未发现数据变更」，**绝不伪造赛果**。
2. **写完即推送**：data.json 写完 + `json.load` 通过 → 立刻 commit/push，早于早报/记忆/单链对齐。
3. **JSON 硬校验**：改完必跑 `json.load`，**只依赖是否抛错**，不要断言字符串里没有 `\n`。复杂转义别塞 `python -c`+单引号，写临时 .py 再删。
4. **先拉后采/先拉后推**：读取或 push 前 `git fetch origin && git rebase origin/main`。禁止强推。
5. **前端测试 `node --test tests/*.test.js`**（不能 `node --test tests/`）。每轮改数据后必跑，0 fail 才推。

## 单链滚动刷新（once 链）
- 全局同时仅 1 个 name 含「刷新」的 **once**（recurring 主任务名也含「刷新」，不算）；建新前先删旧。命名 `刷新链-[YYYYMMDD]-[HHMM]`，`modelId` 必须 `hy3`，`cwds` = `C:/Users/pengz/Documents/GitHub/pingpong-schedule`。
- 刷新时刻：赛前 T=K-1h（仅 T∈(now,now+30h]）；赛中整链只加 1 个 now+30min 点；升序后 30 分钟聚类（≤30min 并入取最晚）；取 ≥now+30min 最早簇为 T_next；无候选则链暂歇。
- **凌晨场日期修正**：data.json 按「08:00~次日08:00」归类，00:00-07:59 的场真实开赛是**次日**；K 须修正。
- **链状态（9/5 06:16 实算）**：候选集 C 恒空 → 暂歇。⚠️ **9/7 06:16 轮是分水岭**：该轮窗口上界 = 9/8 12:16，澳门站 9/8 11:00（T=9/8 10:00）**首次进入 30h 窗口**，必须正常生成 T_next 并建单链。此前各轮（含 9/6 22:16，上界 9/7 22:16）均不满足。

## git / 推送
- 只推 origin（github.com/pengzishang/pingpong-schedule）。提交信息：`赛程刷新_YYYY-MM-DD_HH:MM` / `每日赛程更新 YYYY-MM-DD` / `早报存档与记忆_YYYY-MM-DD_HH:MM` / `记忆归档_...`。
- push 被拒（non-fast-forward）：`stash` 无关 → `fetch` → `reset --hard origin/main` → `checkout <已校验 commit> -- data.json` → commit → push。**勿强推**。
- **rebase 被 unstaged changes 挡住**：先提交改过的 `.workbuddy/memory/MEMORY.md` 再 rebase。
- **每轮开头先查未提交残留**：上一轮可能在 push data.json 后被中断，留下未提交的早报/记忆 → 补提交后再 rebase。
- **curl 校验线上文件**：Git Bash 的 `/tmp` 路径 Windows 版 Python 看不到 → 下载到**仓库内**再删。

## 数据约定
- days 四日期：昨日（带 result 战报，原样保留）+ 今日 + 明日 + 后日。subtitle 固定。
- risk 仅未结束场填：🔴/⚠️/✅ 开头 + 括号大白话标签 + 口语原因建议（台号写 `央视5`/`央视5+`）；整段 2~3 句。已结束省略。
- **【契约 4.6.2】空窗天整段说明写入 day 顶层 `dayNote` 纯字符串，`schedule` 置空 `[]`**。
- **`dayNote` 首句铁律**：`cut = first.search(/[（(：:]/)`，**只有 `cut > 3`** 才取 `substring(0,cut)` 作 lead，否则退回 44 字截断。首句须是「空窗期延续(…复核)。」这类短结论；反例 `9/1(周二)……`（左括号索引 3）必挂。其余要点每条 ≤100 字、**每天 ≥8 条**、`。` 分隔、括号成对；末尾保留「下一站…」句。
- 「下一站…」句内**禁句号**。名单句格式 `出战:男单…/…,女单…/…,缺席:…。`；`parseNextRoster` 只认 `出战|国乒\d*人|报名|参赛|阵容`+冒号；「缺席:」lookahead 会吞到下一关键词 → 用 `背景:` 截断。
- **【坑】`parseNextEventNote` 的名单挂在 `roster` 字段**（`roster.squad`/`roster.absent`），**不是 `nextSquad`/`nextAbsent`**。
- **`nextEvent.note` 追加文本禁用 `→`**（会误入 schedule 段触发时间线分支）。写脚本时加 `assert`。
- video.json 顶层仅 `days[]`，用 `platform`（非 channel）。`renderVideoBlock` **不渲染 result** → 赛果写进 `note` 首句。团体赛按 5.3.1：playerHome/Away 填队名，关键球员进 Info，nationHome 填中国以进「国乒」标签页。
- **【生成脚本幂等陷阱】** 临时 .py 若会 **prepend** note，**重跑前必须 `git checkout HEAD -- data.json`**。更稳做法：脚本开头加 MARK 检查（`if note.startswith(MARK): sys.exit(1)`）。

## 自检必须两层都做
① 解析层 `api.parseDayNote`：lead<20、points≥8、最长≤100、括号配对、next 抽到。
② **渲染层 `buildAbove+buildBelow`**：数 `<section>`（正常值 **4** = 今/明/后 + 下一站卡；昨日空窗天不渲染）与 `pending__points`（正常值 3）。
- 验证手法：`require('./tests/_harness.js')` 拿 `loadApp/loadJSON`（app.js 末尾有 `module.exports`）。
- **`mergeVideo` 可能返回 undefined**（原地改 data）→ 必须 `(r&&r.days)?r:data` 兜底。
- 修前端解析问题优先**在采集端改写法**，不动 app.js。例外：故障字段恰是新契约禁用的 `schedule` → 允许最小修补并**显式通知前端机**。

## 前端已知行为（不是 bug，别误修）
- **昨日空窗天不渲染「昨日战报」区**：`prepareCtx`(app.js:1632) 的 `pastContent` 只看 `day.matches` 有无央视场次。**判定：合理设计**。
- **【铁律·重要战报必须落在"今日" dayNote】**：上一条的直接后果 —— **昨日 dayNote 里写的关键战报页面上根本不显示**。跨日界后上一日的**重要结论必须在今日 dayNote 复述一遍**（带比分）。渲染层自检若发现昨日专属关键词 MISSING，**不是 bug，是没复述** → 回今日 dayNote 补一句，不要改 app.js。
