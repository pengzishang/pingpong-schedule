## 单链滚动刷新（once 链）
- 全局仅 1 个 name 含「刷新」的 **once**（recurring 主任务名也含「刷新」，不算）。命名 `刷新链-[YYYYMMDD]-[HHMM]`，`cwds`=`C:/Users/pengz/Documents/GitHub/pingpong-schedule`，**不传 rrule**，带 `modelId=hy3`。
- 时刻（9.2）：赛前 T=K-1h（仅 T∈(now,now+30h]）；赛中整链只加 1 个 now+30min 点；升序后 30 分钟聚类（≤30min 并入取最晚）；取 ≥now+30min 最早簇为 T_next；无候选则暂歇。**只有 `matches` 参与计算，`schedule` 不算**。凌晨场（00:00-07:59）真实开赛是次日，K 须修正。
- 对齐时**先 list 再删旧建新**；T_next 与现存 once 一致 → 保持不动。

## 数据约定
- days 四日期：昨日（带 result，**原样保留**）+ 今日 + 明日 + 后日。risk 仅未结束场填（🔴/⚠️/✅ + 括号大白话标签 + 口语原因，台号 `央视5`/`央视5+`，2~3 句）；**已填 result 必须移除 risk**。
- **`result` 用取胜者视角**：赢家写在前（即使赢家是 playerAway）。
- **空窗天**整段写入 day 顶层 `dayNote` 纯字符串、`schedule` 置 `[]`；**有真实直播的日子不要写 dayNote**（写了＝死内容）。末尾「下一站…」句内**禁句号**；口诀**「名单句在前、`背景:` 断后」**。
- **【每日收录口径】** 有真实直播的日子**每天固定 4 场 = 国乒 + 日本焦点**，其余在当日早报正文列全。
- **【收官日例外】** 决赛对阵落位后**必须写进当日 `matches`**，宁可从 4 场扩到 6 场。排序交给前端。
- **`schedule` 只在 `matches` 为空的 else 分支渲染**（app.js:1975-2008）→ 有 matches 的日子加 schedule 是死内容。
- **推论**：某日部分对阵待定时，**宁可留 `schedule`，不要只写已定的那几场 `matches`** —— matches 非空会让 schedule 停渲染，待定场次从页面消失。等全部落地（通常当日凌晨轮）再整体升级为 matches。
- **`nextEvent.note` 追加文本禁用 `→`**；**新段落必须插在首句第一个 `。` 之后**（首句括号是 `parseEventMeta` 的 title 锚点）。
- video.json 顶层仅 `days[]`，用 `platform`；`renderVideoBlock` **不渲染 result** → 赛果写进 `note`。团体赛按 5.3.1。

## 前端判据
- **【换站必读】`nextEvent` 改指向新站时必须「名单句在前、`背景:` 断后」**：`parseNextRoster` 缺席段靠 lookahead `[,;。]\s*(出战|国乒|赛程|背景…)` 收尾，收不住会把后面整段采集日志当缺席名单（实测 39~82 条垃圾）。
- **`rosterFromNextEvent` 有 `isNextEventStarted` 闸门**：下一站未开赛 → 名册返回空 → 生存面板只剩窗口内国乒，不会串名单。
- **渲染层 `<section>`＝4，出现「下一站卡」时＝5**（9/14 起 nextEvent 落到窗口外，卡开始显示 → **5 是当前常态**）。
- **测试禁写死「站次」**：名册人数/性别构成/淘汰名单/nextEvent.date/fixture 日期一律以 `computeSurvival`、`isNextEventWithinWindow`、相对 `new Date()` 动态推导（9/14 换站时 4 个用例同时挂）。
- **【铁律】`risk` 禁写「电视看不到」类词**：`riskSaysNoTV` 命中 `手机|APP|app|客户端|咪咕|央视频|不直播|电视上不播|电视不播|只在.*播|只在.*看` → **整场从页面消失**。「想看全用央视频/咪咕」移到早报与 note。**risk 须按当前时刻复核**（赛中轮可能已顺延进续播窗口）。
- 赛事已开打（`ne.date ≤ today`）→ 倒数日徽章不显示。⚠️ `tag--soon` 也是「明天/后天」标签默认 class，自检要看 `day--next`。
- **下一站模块**仅「今/明/后三天都无赛事」时出现；窗口内有赛事时 `day--next`/`emeta__rank-item`/`next__lines` 归零**属正常**。
- **【stage 拆层】** `stage` 是「标题主体 + 补充说明」复合字段，前端 `parseStageDetail` 拆层（①`女单半决赛(七局四胜,胜者进今晚18:30决赛)`；②`女单半决赛(七局四胜),陈熠已晋级今晚18:30决赛`）→ 标题 pill 只留第一个括号外片段，其余渲染成 `.match__stage-detail`。整串在括号里则原样返回，绝不把标题清空。
- 昨日 `matches` 为空 → 该日整段不可见。视频块只在「当日无央视直播」分支渲染。

- `mergeVideo` 可能返回 undefined → `(r&&r.days)?r:data` 兜底；`parseNextEventNote` 必须传 `.note` 字符串。

## 真伪判定
- **【铁律】结论与依据分开判定**：依据错只否定依据，结论另行求证。
- 「矛盾」先查是否描述不完整；**比分顺序先镜像校验**；**时刻取多数**，少数派留痕；量化数字打架只写定性。
- **大比分打架**：自媒体写「4-1」但权威源逐局只给 4 局 → 以**逐局列表**为准，只在早报「未采信」留痕。权威优先级：央视网/奥林匹克频道 > @WTT世界乒联 > 新华社 > 腾讯/搜狐/体坛周报。
- 条件场作废：上轮「若 A 胜则…」本轮必复查。终局后 5~15 分钟发稿 → 开赛超 1 小时仍未发＝仍在进行。
- **命中即判错**：亚运写成「杭州亚运会」（实为日本爱知·名古屋）；澳门站名单出现温瑞博/向鹏/林诗栋；「537 万/2000 积分」＝大满贯口径；同稿内时差 ≠ 6 小时。
- 单源新事实不写 matches，改在 note 以「仅 N 源、待复核」披露。
