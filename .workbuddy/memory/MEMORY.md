## 铁律速查
1. **updatedAt 必刷 + 写完即推送**：每轮必 bump 时间戳；`json.load` 通过后**立即** commit/push，早于早报/记忆/单链对齐。诚实性靠 note 如实写复核结论，**绝不伪造赛果**。
2. **JSON 硬校验**：只依赖 `json.load` 是否抛错。复杂转义别塞 `python -c`+单引号，写临时 .py 再删（收尾 `rm`）。
3. **先拉后采/先拉后推**：读取或 push 前 `git fetch origin && git rebase origin/main`。禁止强推。**每轮开头先查未提交残留**。
4. **前端测试 `node --test tests/*.test.js`**（不能 `node --test tests/`），**0 fail 才推**。
5. **生成脚本幂等**：会 prepend note 的临时 .py 开头加 MARK 检查（`if MARK in note: sys.exit(1)`）。
6. **curl 校验**：Git Bash 的 `/tmp` Windows 版 Python 看不到 → 下载到**仓库内**再删。

## 【9/6 新踩·必看】Git Bash 下 push 挂起 → 改走 PowerShell
- 症状：Git Bash 里 `git push` 无输出挂死（`git ls-remote` 却 0.6s 正常返回）。
- 定位法：`GIT_TERMINAL_PROMPT=0 git -c credential.helper= push` → 秒报 `could not read Username`，**证明网络通、是 GCM（`credential.helper=manager`）卡在 GUI 登录等待**。
- **解法：直接用 PowerShell 工具跑 `git push origin main`，一次成功**（LASTEXITCODE=0）。以后凡挂起，先 PowerShell 直推，别在 Git Bash 死等。
- 连带坑：`pkill -f "git push"` 会瞬时弄坏 `origin/main` 引用（`rev-parse` 报 Needed a single revision），过几秒自愈，别慌着修。

## 【9/7 新踩·必看】GitHub 直连 Connection reset → 走本地代理 127.0.0.1:7897
- 症状：`git fetch/push` 与 `curl https://github.com` 均报 `Recv failure: Connection was reset`（Git Bash 与 PowerShell 都一样），不是 GCM 问题。
- **解法：本机有代理 `http://127.0.0.1:7897`（环境变量 `TELEGRAM_PROXY` 暴露）。在 PowerShell 里先设**
  `$env:http_proxy="http://127.0.0.1:7897"; $env:https_proxy="http://127.0.0.1:7897"`，**再 fetch/rebase/push，一次成功**。
  验连通：`curl -x http://127.0.0.1:7897 -o /dev/null -w "%{http_code}" https://github.com/` → 200。
- curl 拉 raw.githubusercontent.com 校验远端文件时**同样要带 `-x` 代理**。
- 判定顺序：push 失败 → 先 curl 测直连 → 不通就上代理，别反复重试干等。

## 【9/7 新踩·必看】每轮开头必查 `git status`（残留检测）
- 9/7 轮发现上一轮（9/6 15:05）**改完 data.json/video.json 却没 commit 也没 push**，工作区脏、rebase 直接失败。

## 单链滚动刷新（once 链）
- **【9/7 新踩】创建 once 时不要传 `rrule`**（once 只需 `scheduledAt`）。误传 `FREQ=MINUTELY` 会被原样存下，有重复触发风险 → 必须删掉重建、让 rrule 为空串。
- 自检脚本调用姿势：`api.buildAbove(api.prepareCtx(data), data)` + `api.buildBelow(ctx, data)`，**不是传 now**。
- 全局同时仅 1 个 name 含「刷新」的 **once**（recurring 主任务名也含「刷新」，不算）。命名 `刷新链-[YYYYMMDD]-[HHMM]`，`modelId` = `hy3`，`cwds` = `C:/Users/pengz/Documents/GitHub/pingpong-schedule`。
- 刷新时刻：赛前 T=K-1h（仅 T∈(now,now+30h]）；赛中整链只加 1 个 now+30min 点；升序后 30 分钟聚类（≤30min 并入取最晚）；取 ≥now+30min 最早簇为 T_next；无候选则链暂歇。**凌晨场（00:00-07:59）真实开赛是次日，K 须修正**。
- **链状态（9/7 07:14 实算·已建链）**：窗口 (9/7 07:20, 9/8 13:20]。C = {9/8 10:00（对应 11:00 场）、9/8 11:45（对应 12:45 场）}；9/8 18:30 场 T=17:30 超窗口不纳入。两簇相隔 1h45m > 30min → 取最早簇 **T_next = 9/8 10:00** → 已建 once「刷新链-20260908-1000」（modelId=hy3）。⚠️ 9/7 15:00 主任务轮会重新对齐：届时 9/8 18:30 场（T=17:30）将进入窗口，可能改排更晚的簇，**务必按 9.3 先 list 再删旧建新**。

## 数据约定
- days 四日期：昨日（带 result，**原样保留**）+ 今日 + 明日 + 后日。risk 仅未结束场填（🔴/⚠️/✅ + 括号大白话标签 + 口语原因，台号写 `央视5`/`央视5+`，整段 2~3 句）。
- **【契约 4.6.2】空窗天整段说明写入 day 顶层 `dayNote` 纯字符串，`schedule` 置空 `[]`**。
- **`dayNote` 首句铁律**：`cut = first.search(/[（(：:]/)`，**只有 `cut > 3`** 才取 `substring(0,cut)` 作 lead（反例 `9/1(周二)…` 左括号索引 3，必挂）。要点每条 ≤100 字、**每天 ≥8 条**、`。` 分隔、括号成对；末尾保留「下一站…」句。
- 「下一站…」句内**禁句号**。名单句 `出战:男单…/…,女单…/…,缺席:…。`；**口诀「名单句在前、`背景:` 断后」**——`缺席:` 的 lookahead（app.js 第 984 行）会吞掉后续全部文本（实测 absent=68），必须用 `背景:` 截断（该 lookahead 关键词表含 `背景`）。
- **`nextEvent.note` 追加文本禁用 `→`**（触发时间线分支），脚本里加 `assert`。
- video.json 顶层仅 `days[]`，用 `platform`（非 channel）；`renderVideoBlock` **不渲染 result** → 赛果写进 `note` 首句。团体赛按 5.3.1。
- **「有直播但对阵未定」的日子（如 9/8）**：写 `schedule` + `pending:true`，**不要写 dayNote**（`renderDaySection` 是 else-if，dayNote 不会渲染＝死内容）。

## 自检两层必做
① **解析层** `api.parseDayNote`：points≥8、最长≤100、括号配对、next 抽到、squad/absent 与 dayNote 一致。
② **渲染层** `buildAbove+buildBelow`：`<section>` 正常值 **4**（今/明/后 + 下一站卡；昨日空窗天不渲染）。
- **⚠️ `pending__points` 不是固定 3**：它只统计 dayNote 要点块。若某天有真实直播（走 `sched__row`），该日不产出要点 → 本轮为 **2** + `sched__row`=2，属正常，别误判。
- 手法：`require('./tests/_harness.js')`。**`mergeVideo` 可能返回 undefined** → 必须 `(r&&r.days)?r:data` 兜底。
- `parseNextEventNote` 必须传 `.note` **字符串**，传对象会走 `String(obj)` = `"[object Object]"`，roster 恒为 0。名单挂在 **`roster`** 字段，不是 `nextSquad`/`nextAbsent`。
- **【9/6 新踩·排行榜只在 meta 块渲染】** `maybeRankList` 要求「`标签:项1 / 项2 / …`」且**每项含数字、≥4 项**；而 `parseNextEventNote` 按关键词分块（顺序 isTV>isSeeds>isSched>isSquad），**子句里出现「种子/排名/参赛/国乒/出战」就会被分到 seeds/squad 块，排行榜不渲染** → 位次表措辞须避开这些词。本轮用「澳门站男单位次(数字越小越靠前,…):1 莫雷加德 / 2 …」落进 meta，得 16 个 `emeta__rank-item`（测试要求 ≥10）。
- 修前端解析问题优先**在采集端改写法**，不动 app.js。

## 前端已知行为（不是 bug，别误修）
- **昨日空窗天不渲染「昨日战报」区**（`pastContent` 只看 `day.matches`）→ **昨日若 matches 为空，该日整段（含 dayNote 与 video 块）都不可见**，故 video.json 里给"昨日"写内容属死内容，但保留无害。
- **视频块只在「当日无央视电视直播」分支渲染**（`renderVideoBlock` 在 else 分支）→ 有央视的日子（如 9/8、9/9）写 video.json 不会显示，不必写。
- **【铁律·重要战报必须落在"今日" dayNote】**：跨日界后上一日的重要结论**必须在今日 dayNote 复述**（带比分）。自检发现昨日专属关键词 MISSING，不是 bug，是没复述。
