# 项目记忆: pingpong-schedule 央视乒乓赛程

> 完整指令在项目根 `采集说明.md`（唯一指令源）。本文件只记**踩坑与判据**，不重复指令书。

## 铁律速查
1. **updatedAt 必刷**：每次跑完无论有无变更都 bump + push。用户原话「无变更也要显示时间变了」。诚实性靠 note 如实写「本轮复核未发现数据变更」，**绝不伪造赛果**。
2. **写完即推送**：data.json 写完 + `json.load` 通过 → 立刻 commit/push，早于早报/记忆/单链对齐（8/23 事故：推送排末尾被打断）。
3. **JSON 硬校验**：`Edit` 的 `\n` 有落盘成真换行的风险 → 非法 JSON 会让前端 `res.json()` 抛错、网页停旧数据。改完必跑 `json.load`，**只依赖是否抛错**，不要断言字符串里没有 `\n`。复杂转义别塞 `python -c`+单引号，写临时 .py 再删。
4. **先拉后采/先拉后推**：读取或 push 前 `git fetch origin && git rebase origin/main`。禁止强推。

## 单链滚动刷新（once 链）
- 全局同时仅 1 个 name 含「刷新」的 once；建新前先删旧。命名 `刷新链-[YYYYMMDD]-[HHMM]`，`modelId` 必须 `hy3`，`cwds` 用 Windows 绝对路径 `C:/Users/pengz/Documents/GitHub/pingpong-schedule`（无前导斜杠会被误拼到 Program Files）。
- 刷新时刻：赛前 T=K-1h（仅 T∈(now,now+30h]）；赛中整链只加 1 个 now+30min 点；升序后 30 分钟聚类（≤30min 并入取最晚）；取 ≥now+30min 最早簇为 T_next；无候选则链暂歇。
- **凌晨场日期修正**：data.json 按「08:00~次日08:00」归类，00:00-07:59 的场写在「今日」date 下但真实开赛是**次日**；K 须修正，否则全部漏算、链假暂歇。
- 赛中区间 = 当前 ∈ [K-30min, K+3h]。`live` 字段：已开赛且 result 为空时写进行中局分；result 一出即清 live。前端 60s 轮询。

## git
- 只推 origin（github.com/pengzishang/pingpong-schedule）；gitee 已弃用。
- 提交信息：`赛程刷新_YYYY-MM-DD_HH:MM` / `每日赛程更新 YYYY-MM-DD` / `早报存档与记忆_YYYY-MM-DD_HH:MM`。
- push 被拒（non-fast-forward，前端机抢先）：`stash` 无关 → `fetch` → `reset --hard origin/main` → `checkout <已校验 commit> -- data.json` → commit → push。**勿强推**。

## 数据约定
- days 四日期：昨日（带 result 战报，原样保留）+ 今日 + 明日 + 后日。subtitle 固定。
- risk 仅未结束场填：🔴/⚠️/✅ 开头 + 括号大白话标签 + 口语原因建议（台号写 `央视5`/`央视5+`）；⚠️ 另起一句证据可靠性，📊 另起一句人头对战；整段 2~3 句。已结束省略。
- 「下一站…」句内**禁句号**，句内用逗号分隔出战/缺席名单。
- **nextEvent.note 名单句必须写成 `国乒N人:男单…/…,女单…/…,缺席:…。背景:…`**。原因：`parseNextRoster` 正则只认 `出战|国乒\d*人|报名|参赛|阵容`+冒号，**「国乒男单5人:」不匹配 → 出战卡解析为 0 人**；且「缺席:」lookahead 会一路吞到下一个关键词（如「直播渠道:」），把后续整段当缺席人名。用 `背景:` 截断。日期块里的「下一站…出战:」写法不受影响。
- **【契约 4.6.2】空窗天整段说明写入 day 顶层字符串 `dayNote`，`schedule` 置空 `[]`**，禁止再塞 `schedule` 伪 record。前端 `parseDayNote` 拆成「lead + points + 下一站区块」。
- **`dayNote` 首句铁律**：`cut = first.search(/[（(：:]/)`，**只有 `cut > 3`** 才取 `first.substring(0,cut)` 作 lead，否则退回 44 字截断 → 测试挂。首句必须是「空窗期延续(…复核)。」这类短结论；反例 `9/1(周二)……`（左括号在索引 3）必挂。其余要点每条 ≤100 字、用「。」分隔、括号成对；末尾保留「下一站…」句。
- **验证 dayNote 必须两层都做**：① 解析层 `api.parseDayNote(day.dayNote)` 查 lead<20、points≥8、最长≤100、括号配对、next 抽到；② **渲染层 `buildAbove+buildBelow` 数 `<section>` 与 `pending__points`**。单看 ① 正常不代表页面正常（9/1 教训：四天被 `dayHasContent` 整体折叠，`<section>` 只剩 1 个）。
- 修前端解析问题优先**在采集端改写法**，不动 app.js（前端由另一台机器维护）。**验证手法**：`node -e "const {loadApp,loadJSON}=require('./tests/_harness.js'); ..."` —— app.js 末尾有 `module.exports` 且顶层执行带 `typeof document` 守卫，Node 里可直接 require，**不必再手工按花括号切函数**（旧做法已废弃）。
- **上述例外判据**：若 `dayHasContent` 只认 `matches`/`videoMatches`/`schedule` 而故障字段恰是新契约禁用的 `schedule`，采集端无合规字段可绕过 → 允许最小修补并**显式通知前端机**（9/1 已在 app.js:683 后补 `if (typeof day.dayNote === 'string' && day.dayNote.trim()) return true;`）。
- video.json 顶层仅 `days[]`，用 `platform`（非 channel）。`renderVideoBlock` **不渲染 result** → 赛果写进 `note` 首句。团体赛按 5.3.1：playerHome/Away 填队名，关键球员进 Info，nationHome 填中国以进「国乒」标签页。

## 采集环境（踩过的坑）
- **epg 参数被丢**：`sports.cctv.com/epg?channel=cctvX&date=YYYY-MM-DD` 对 **CCTV-5 / CCTV-16 会间歇性丢参数、返回默认页**。判别：返回条目链接是否仍带 `?channel=…&date=…`，丢了的必重抓。**改用 `sports.cctv.com/epg/index.shtml?channel=cctvX&date=YYYY-MM-DD` 稳定命中**。另可能返回旧日期缓存，须核对日期导航栏高亮。
- `WebFetch tv.cctv.com/live/cctv5plus/` **9/1 起失效，只返回频道导航**；`/cctv5` 抓不到 → CCTV-5 走 index.shtml + 搜狐/网易当日汇总稿交叉。
- **咪咕三入口**（专区常只返回 banner 与资讯栏、拿不到逐日预约表）：① **banner**（「正播…」/「X时播…」= 当日是否有直播）；② **资讯栏首条**（如「19时播WTT阿拉木图站 倪夏莲出战 方博男双迎首秀」= 当日时段官方一手）；③ **「精彩回放」区**（补已结束场次官方比分 + 译名核对）。**排期会变，每轮必重抓，禁止沿用上轮时段**；变化要在文案写明「此前显示 X、现在显示 Y，以开播前页面为准」。

## 真伪判定（避免误杀 & 避免被骗）
- **AI 幻觉赛果**：k.sina.com.cn 大量「本文由AI生成」稿把预测写为既成赛果。采信前做可行性校验：K + 局数×8min ≤ 当前，否则排除。
- **旧闻翻新**：「XX 怎么看回放/直播」体裁常把旧赛事当当日热点；鉴别 = 拿赛事名+对阵反搜原始通稿核对发布日。
- **跨赛事旧战报**：同一对阵相邻两站重复，旧站战报霸屏；鉴别 = 核对「下一轮对手」是否与本站签表一致。
- **单一平台多稿矛盾 ≠ 事件为假**（邓亚萍杯教训）。分层：① 事件要素多平台一致 → 为真；② 仅直播渠道未官宣 → 只影响是否写文件；③ 个别夸张细节无出处 → 只剔该细节。处置：不写入但必须在 note + 早报留痕。
- **条件场作废**：上轮「若 A 胜则某日某时」本轮必查条件是否成立；A 出局则删条件句并补明确否定句，不能静默删。
- 权威源优先级：@WTT世界乒联 微博（uid 7556183438）逐局赛果 = 官方口径，单源可写 result；虎扑/直播吧/腾讯新闻正文次之。该号与 @咪咕体育 终局后 5~15 分钟发稿 → 开赛超 1 小时仍未发 = 仍在进行，别套旧比分。
- WTT 冠军赛男女单各 32 人正赛、**不设资格赛**；「需从资格赛打起」一律判错，正确是「从非种子位置打起」。

## 前端已知行为（不是 bug，别误修）
- **昨日空窗天不渲染「昨日战报」区**：`prepareCtx`(app.js:1632) 的 `pastContent` 只看 `day.matches` 有无央视场次（`dayHasContent` 只用在 `upcomingContent`）→ 昨日 matches 为空时该天整块不出现。**判定：合理设计**，对长辈更干净。**不改 app.js、不通知前端机**；dayNote 完整留档，其中对今天有用的信息（首秀时间、直播时段）要同步进当天文案。
- 因此「`<section>` 数 = 4」= 今天/明天/后天三个日期块 + 下一站卡；昨日不算。这是正常值。

## 直播渠道判定
- **主办方乒协稿只提当地台 ≠ 国内无版权**（连续三轮错判：阿拉木图站 9/1 实有咪咕直播）。低级别站次**必查咪咕专区一手排期**。
- 有直播但对阵未公布 → 按 5.3 无法填 playerHome/Away，**不要硬凑**「VS 多场同时进行」（属编造），改在当日 dayNote 写明时间+平台+观看方式，满足八·乙「不静默留空」。
- **国乒零报名的全外协低级别站即使有咪咕直播也不写 video.json**：对长辈无意义；但必须在 note 留痕理由。
- **国乒选手的海外联赛（如樊振东德甲）有国内平台转播 → 必须写 video.json**，按 5.3.1 团体赛写法。
