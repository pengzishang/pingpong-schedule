# 🏓 国乒赛事日历(China Table Tennis Schedule)

> 央视直播的国乒乒乓球比赛时间表,**每天自动更新**,大字大按钮,长辈也能看清。

## 📺 在线访问

- 🌍 **主站(每日自动更新)**:**https://pengzishang.github.io/pingpong-schedule/**
- 🇨🇳 国内访问可能需要稳定的网络环境,GitHub Pages 在国内的可达性时好时坏,影响观看请见下方说明

## ✨ 功能特点

- **国乒央视直播聚焦**:只展示央视(CCTV-5 / CCTV-5+ / CCTV-16)转播的**国乒**比赛;羽毛球、中超等其他体育不混入(长辈只看国乒,无关内容一律隐藏)
- **今日 / 未来赛程**:每天滚动展示央视转播的国乒比赛时间表;当日无直播时显示「今日无直播」空窗说明卡
- **下一站国乒赛事预览卡**:对即将到来的重点赛事做六块结构化展示——赛事信息 / 国乒阵容 / 焦点与种子 / 赛程时间线 / 直播安排 / 信息来源
- **空窗横幅**:若未来 3 日内都没有央视国乒比赛,页面顶部显示「离最近一场国乒比赛,还有 X 天」,下方各处不再重复倒数
- **昨日战报**:仅在有比赛的日子展示回顾;纯空窗天(只有说明、无比赛)自动隐藏,不留空白栏目
- **视频平台直播兜底**:若当天央视不转播国乒,但咪咕/央视频有直播,在「今日无直播」位置兜底显示,并标注「电视上看不到,需用手机/平板/电脑看」
- **多源交叉认证**:每个场次时间经 ≥4 个独立来源验证,**同稿转载不算独立源**,数据可信
- **适老化设计**:18px+ 大字号、高对比 navy+red 配色、大触控按钮(≥48px)、无装饰动效、手机竖屏友好
- **窄屏优化**:节目行在窄屏下「时间 + 台标」竖排堆叠于左侧,节目名独占右侧宽列自然换行,不再一字一断
- **国旗标识**:每个选手旁显示所属国家/地区国旗(emoji),长辈一眼可辨
- **赛事标签**:每场比赛标注所属赛事(如 "WTT 横滨冠军赛")
- **插播风险标注**:与央视其他固定栏目(如《体育新闻》)重叠的场次,会明确标注并建议用央视频兜底
- **未公布场次**:有转播安排但对阵未公布时,展示央视转播时段卡片,不硬凑数据

## 📊 数据来源与认证规则

每个比赛场次的**具体时间**必须经过至少 4 个独立来源交叉认证;时间冲突时取**多数源时间(众数原则)**。

| 来源类型 | 代表 |
|---------|------|
| 央视官网 | sports.cctv.com |
| 独立节目单 | 电视猫 tvmao.com |
| 主流体育媒体 | 新浪体育、腾讯新闻、网易体育、搜狐体育、今日头条 |
| 视频平台 | 咪咕体育、PP 体育 |

> 同一篇报道被多家转载只计 1 个独立源,只有独立编辑/独立域名才算独立源。

## 🗂 项目结构

```
pingpong-schedule/
├── index.html          # 页面骨架:结构 + <link style.css> + <script app.js>(body 末尾,无 defer)
├── style.css           # 全部样式(原内联 <style> 抽离,navy+red 适老化主题、.gap-banner、.pending__row 等)
├── app.js              # 全部渲染逻辑(原内联 <script> 抽离;含 fetch('data.json') 相对路径加载)
├── data.json           # 央视直播数据源(另一台机器整文件重写,定时更新)
├── video.json          # 视频平台(咪咕/央视频)直播数据源(另一台机器额外写入,本机不抓)
├── update_data.py      # 数据局部更新脚本(示例/手动维护用)
├── build_report_*.py   # 早报构建脚本
├── .github/
│   └── workflows/
│       └── deploy-pages.yml   # GitHub Pages 部署(整仓上传,零构建)
├── .nojekyll           # 禁用 Jekyll,确保 Pages 直接托管静态文件
└── README.md           # 本文件
```

> 拆分说明:原 89.7KB / 1850 行的单文件 `index.html` 已拆分为「骨架 + 样式 + 脚本」三部分,行为严格等价、零构建。改动样式进 `style.css`、改渲染逻辑进 `app.js`、改结构进 `index.html`。

## 🏗 技术架构

- **纯静态、零构建**:无 npm / 打包工具,GitHub Pages 直接托管 `index.html` / `style.css` / `app.js`
- **客户端渲染**:`app.js` 通过 `fetch('data.json?t=' + Date.now())`(相对路径,`cache: 'no-store'`)加载数据并渲染;脚本置于 body 末尾同步执行,无需 `defer`
- **零构建部署**:`.github/workflows/deploy-pages.yml` 将整个仓库作为 Pages artifact 上传(无需构建步骤)
- **双机同步**:另一台机器定时重写 `data.json`(央视直播)并 push;视频平台(咪咕/央视频)直播单独写入 `video.json` 一并推送。前端只读取、不修改数据,部署链路与数据更新互不干扰

## 🔄 数据自动更新流程

每天 0:00 / 8:00 / 16:00,自动化任务自动执行:

1. 从 ≥6 个独立来源采集赛程数据
2. 对每个比赛场次做多源交叉认证
3. 生成 Markdown 早报存档到本地
4. 生成/更新本仓库的 `data.json`,提交并推送到 GitHub
5. GitHub Pages 自动构建并部署,网页实时同步

## 🔁 刷新调度策略(赛前 + 赛中统一调度)

网页数据除了每 8 小时的主任务全量刷新,还会按比赛时间自动加密盯盘,既保证"开打前数据最新",又把刷新频率锁死:

- **赛前轨道**:每场 `开赛前 1 小时` 自动建一次轻量刷新,确保开打那一刻数据最新。
- **赛中轨道**:比赛开打后若还没出比分,自动建刷新任务(开赛+1h 起、30 分钟级追查、3 小时上限)盯到出结果。
- **防频繁**:所有刷新共用一套任务注册表,**任意两个刷新时间相差 ≤30 分钟就合并成一个**(因为每次刷新都是全局全量,合并零代价);不加单日硬上限,最坏约 2 次/小时。
- **轻量**:赛前/赛中这些自动刷新只重采数据 + 更新 `data.json` + 推送,**不重复生成长篇早报**;完整早报仍只由每 8 小时主任务产出。
- **并行采集(subagent 编排)**:主任务与这些自动刷新在「采集」阶段并行派发 3~4 个采集 subagent(按来源组分工:①央视官网+电视猫 ②新浪/腾讯/今日头条 ③网易/搜狐/直播吧 ④WTT/咪咕),各 subagent 只回传结构化 JSON、不写文件;由编排器串行收口做交叉认证与写 `data.json`,杜绝写冲突。若运行时无法派 subagent,则降级为编排器自身一次性并行 WebFetch。此机制经「受控验证探针」确认自动化运行时可派 subagent 后全量启用(2026-08-07)。

## 📱 视频平台直播(video.json)

外婆平时只看央视电视,但遇上央视不转播国乒的日子,页面会在「今日无直播(电视)」位置兜底显示**视频平台(咪咕/央视频)的直播**,并明确标注「电视上看不到,需用手机 / 平板 / 电脑看」,给老人家指条手机上看的路。

> 设计铁律:视频直播**只在当天没有央视电视直播时**兜底显示(有央视就只显央视);外婆只看电视,视频块用紫色强调、与央视蓝卡明显区分,绝不和电视搞混。

### 数据来源(另一台机器负责,本机不抓)

`video.json` 与 `data.json` **完全解耦**——前者由另一台机器在采集管线里把原本丢弃的咪咕/央视频数据捡回来、另存成独立文件。这样做的好处:另一台机器整文件重写 `data.json` 时根本碰不到 `video.json`,央视主页面零风险。

**交给另一台机器维护者的三件事**:

1. **别再把咪咕/央视频的数据扔了**:采集管线里已有抓「WTT/咪咕」的环节(subagent ④),之前因"外婆只看央视"采完丢弃,现在把它留下来。
2. **另存成 `video.json`**,按下面的字段格式输出(按 `date` 与 `data.json` 对齐即可合并):

   | 字段 | 说明 |
   |------|------|
   | `date` | `YYYY-MM-DD`,和 data.json 同键 |
   | `matches[].time` | 直播时间 `HH:MM` |
   | `matches[].platform` | 平台名,如 `咪咕视频` / `央视频` |
   | `matches[].tournament` / `stage` | 赛事 / 轮次 |
   | `matches[].nationHome` / `nationAway` | 对阵双方国籍(供国旗 + 国乒/日韩筛选复用) |
   | `matches[].playerHome` / `playerAway` / `player*Info` | 选手名 / 排名等附加信息 |
   | `matches[].note` | 可选说明 |

   只放**有视频直播**的日子,纯录像/录播不进。

   > **判定规则**:把 `channel` 命中 `咪咕|央视频|腾讯体育|优酷|爱奇艺|客户端|app|网页|网端` 的场次挑出来写进 video.json(这些正是 `data.json` 里被央视判定排除、不进电视的场次);`channel` 为 `CCTV`/央视的只进 `data.json`,**不要**写进 video.json。
   >
   > **字段名注意**:video.json 源文件 day 用 `matches` 字段(如上表);前端合并后内部才叫 `videoMatches`。采集端**只需按源格式 `matches` 输出**即可,不要直接写 `videoMatches`。

3. **推送时带上它**:`git add data.json video.json && commit && push`。**勿用会删新文件的强制推送**——本仓库已先提交一份带"示例/待覆盖"标注的占位 `video.json`,采到真数据后直接覆盖即可。

### 前端行为

- 无央视电视直播、但有视频直播的日子 → 显示「📱 视频平台直播」块(紫色),含每场时间、平台、对阵、国旗。
- 视频场次跟随「全部 / 国乒 / 日韩」tab 显隐(国乒 tab 下仅显国乒视频)。
- 顶部「离最近一场国乒比赛,还有 X 天」空窗横幅**只看央视**,视频直播不计入(避免与视频块自相矛盾)。
