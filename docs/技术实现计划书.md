## 3. ES module 拆分：**本轮不做**（含 M3 前置条件）

### 为什么不拆（实测依据）

| 维度 | 结论 |
|---|---|
| 对测试成本 | ≈0（Node 22.22.3 实测：`require()` 可直接拉 ESM，跨目录相对 import 正常；**唯一硬禁止顶层 await**） |
| 对病灶 | **不解决任何已复现病灶**——R-1/R-2/R-3 的根治手段是结构化契约，与文件组织无因果关系 |
| 新增风险 1 | `lib/` 漏进 staging → import 404 → **真白屏** |
| 新增风险 2 | `max-age=600` 下出现「新 index.html + 旧 lib 模块」的 **10 分钟缓存错配窗口** |

**架构师的反直觉结论（建议收录）**：单文件 `app.js` 是**唯一不可能版本错配的部署单元**
——index.html 与 app.js 要么都新、要么都旧，物理上不存在中间态。这个优势值得 2458 行的可维护性代价。

### M3 若真要拆的 5 条前置条件（缺一不拆）

1. 结构化契约已上线并全量回填（`outlook`/`roster`/`status`/`tvAvailable` 连续 7 天出现）
2. 解析器已实际归零（`_fromDayNote`/`_fromNote` 断言连续 7 天绿）
3. CI 部署门禁已跑稳 ≥2 周
4. **immutable 资源路径方案已落地**（最难）——零构建下需人工改 index.html 的 src，双机节奏下必错
5. **引用可达闭包已在 CI 跑通**

> 若第 4 条无干净解法，**M3 的正确决策是继续不拆**，而非"拆得更谨慎"。

## 4. 数据契约 v2 与 v1→v2 迁移

### 新增字段（已定稿）

```jsonc
{
  "schemaVersion": 2,
  "days": [{
    "date": "2026-09-27",
    "mode": "matches",              // matches | schedule | gap
    "matches": [{
      "time": "11:00",
      "channel": "CCTV-5",
      "tvAvailable": true,          // 替代 risk 文案判定（R-1）
                                    // ⚠️ 缺省 = 两级回落 tvAvailable ?? isCCTVChannel(channel)
                                    //    不是「缺失=true」——后者会让咪咕进电视表，违反铁律
      "status": "finished",         // upcoming | live | finished
      "confirmed": true,            // 对阵是否已确定（Q2 逐场并存已定+待定）
                                    //   false → 打「⏳ 待确认」标，不删场
      "playerHome": "...", "playerAway": "...",
      "result": "...",              // 仅 finished 带
      "risk": "..."                 // 仅 upcoming/live 且确有插播提示时带；finished **不带**
    }],
    "outlook": { "lead": "...", "points": [...], "next": "..." }   // 替代 dayNote 散文
  }],
  "nextEvent": { "date": "...", "roster": {...}, "absent": [...], "tv": [...] }
}
```

### `adaptV1toV2()` 放置位置（唯一正确解）

放在 **`loadData()` 返回之后、`writeCache()` 之前**（`boot()` 的 `.then()` 内）：

```js
loadData().then(function (data) {
  disarmSlowTimer();
  var v2 = adaptV1toV2(data);   // ← 插在这里（Z1 出口，全应用唯一入口）
  writeCache(v2);               // ← 缓存必须存 v2
  ...
})
```

**三条理由**：
1. **单一入口**——`loadData()` 是全应用唯一数据入口，放在其出口不可能漏
2. **缓存必须存 v2**——若放 `writeCache` 之后，缓存是 v1、网络是 v2，`readCache()` 返回结构与线上不同 → **必现 bug**
3. **测试可直连**——不需要 DOM，直接单测

**绝对不要放在 `module.exports` 段**（浏览器里 `module` 未定义整段跳过 → 线上不执行、测试却全绿 = 最危险的假绿）

### 失败降级（脏数据不得抛异常）

三层：整体 try/catch → schemaVersion 判定 → 逐字段独立 try。
**不做校验**（那是契约测试职责）、**不做判定**（Z4 职责）、**不猜字段**（v1 没有的 `status` 留 undefined 走回落）。

**`_fromDayNote` / `_fromNote` 标记** = 解析器退役开关：加断言「真实 data.json 里 `outlook._fromDayNote` 不得为 true」，
把"解析器什么时候能删"从口头约定变成可执行判据。

### 解析器删除时机（已拍板）

**结构化字段上线后才删**，过渡期保留只读渲染。
架构师实测：当前 `data.json` 确实有 `dayNote` 与 `nextEvent.note`，删了会让**空窗期说明与下一站名单直接消失** = 功能回退。

## 5. Pages 部署方案

### 5.1 staging 白名单（**本轮立即做**）

⚠️ **纠正计划书原文**：H-01 写的「`path` 改显式文件白名单」**技术上不可实现**——
`upload-pages-artifact@v3` 的 `path` 只接受**单目录**（tar 仅排除 `.git/.github`，无 glob、无文件列表）。

```yaml
      - name: 测试门禁（零依赖）
        run: node --test tests/logic.test.js tests/render.test.js tests/data-contract.test.js

      - name: 构建 staging 目录
        run: |
          set -euo pipefail
          rm -rf _site && mkdir -p _site
          cp index.html style.css app.js data.json video.json .nojekyll _site/
          # 【M3 扩展位】拆 ESM 后追加：cp -r lib _site/lib/ ; cp boot.js _site/

      - name: 校验 staging（快速失败，防白屏）
        run: |
          set -euo pipefail
          for f in index.html style.css app.js data.json video.json .nojekyll; do
            test -f "_site/$f" || { echo "::error::staging 缺少 $f"; exit 1; }
          done

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3   # ⚠️ 禁止升 v4/v5/main，见下
        with:
          path: '_site/'
```

### 5.2 `.nojekyll` 升级陷阱（🔴 必守）

`upload-pages-artifact` 的 `main` 分支已新增 `include-hidden-files`（默认 `false`）→ tar 追加 `--exclude=.[^/]*`
→ `.nojekyll` 被**静默排除** → Jekyll 接管 → 站点故障。

**必须**：锁死 `@v3` 并加注释；若升级须同时显式传 `include-hidden-files: true`。

### 5.3 CI 测试门禁（已拍板采纳）

采集端每 8h 自动推送 → 自动部署 → 零校验直达外婆手机，是**最现实的投毒路径**。
在 `configure-pages` 之后插入 `node --test`。

> ✅ 已核实不会误伤：当前 `data-contract.test.js` 对 `schemaVersion/tvAvailable/status/confirmed` 的断言数为 **0**，
> 只验 v1 形态，因此 M2 过渡期采集端仍产 v1 时不会被门禁阻塞。

### 5.4 暴露面：两种必须分开（已拍板）

| 面 | 现状 | 处置 |
|---|---|---|
| **A 面（Pages 站点）** | 实测 191 个非站点文件返回 200（含 `采集说明.md`、129 个 memory、50 篇早报、含 `C:\Users\pengz\` 的僵尸脚本） | **修**：staging 白名单 |

### 5.5 引用可达闭包（M3 关键防漏拷）

## 10. 回滚预案

- 代码类：`git revert <commit>`（依赖「每步即推」纪律）
- 部署类：`deploy-pages.yml` 改回 `path: '.'` 即可恢复
- **⚠️ `cancel-in-progress: true` 的约束**：被 cancel 过的 SHA 重发会立刻再次 cancelled
  → 回滚**必须造新 SHA**（`git commit --allow-empty`），**不能 rerun**
